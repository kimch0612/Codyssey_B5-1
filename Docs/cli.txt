B5-1 Mini Redis CLI 입력과 기대값

[사용법]
각 시나리오는 새로 실행한 mini-redis 세션에서 번호 순서대로 진행한다.
`mini-redis>`는 프롬프트 표시이므로 직접 입력하지 않는다.
이 문서는 REPL에 입력할 명령과 화면에서 확인할 기대값만 다룬다.

주의할 값:
- `KEYS`의 출력 순서는 요구사항상 고정되지 않는다. 번호보다 키의 포함 여부를 확인한다.
- `TTL`의 양수 결과는 입력 사이에 흐른 시간에 따라 달라진다.
- 큰따옴표는 공백을 포함한 하나의 값을 만들기 위한 입력 구분자이며 저장 값에는 포함되지 않는다.

================================================================
1. 기본 문자열 명령 — 하나의 새 mini-redis 세션
================================================================

[D01] 빈 저장소의 KEYS

입력:
KEYS

기대값:
(empty array)

----------------------------------------------------------------

[D02] 빈 저장소의 DBSIZE

입력:
DBSIZE

기대값:
(integer) 0

----------------------------------------------------------------

[D03] 공백과 한글이 있는 값 저장

입력:
SET greeting "안녕 세상"

기대값:
OK

실제 저장 값은 `안녕 세상`이며 구분용 큰따옴표는 저장되지 않는다.

----------------------------------------------------------------

[D04] 저장한 값 조회

입력:
GET greeting

기대값:
"안녕 세상"

성공한 GET이므로 greeting의 LRU 위치가 MRU로 갱신된다.

----------------------------------------------------------------

[D05] 존재하는 키 확인

입력:
EXISTS greeting

기대값:
(integer) 1

----------------------------------------------------------------

[D06] TTL을 설정하지 않은 키

입력:
TTL greeting

기대값:
(integer) -1

----------------------------------------------------------------

[D07] 두 번째 키 저장

입력:
SET number 0

기대값:
OK

문자열 `0`도 정상적인 값이며, 값의 참·거짓과 키 존재 여부는 관계가 없다.

----------------------------------------------------------------

[D08] 전체 키 확인

입력:
KEYS

기대 키:
"greeting", "number"

예시 출력:
1. "greeting"
2. "number"

두 키의 출력 순서는 달라질 수 있다.

----------------------------------------------------------------

[D09] 키 개수 확인

입력:
DBSIZE

기대값:
(integer) 2

----------------------------------------------------------------

[D10] 기존 키 덮어쓰기

입력:
SET greeting "다시 안녕"

기대값:
OK

새 LRU 노드를 추가하지 않고 기존 StoreEntry의 값을 바꾸며, 해당 노드를 MRU로 이동한다.

----------------------------------------------------------------

[D11] 덮어쓴 값 확인

입력:
GET greeting

기대값:
"다시 안녕"

----------------------------------------------------------------

[D12] 존재하는 키 삭제

입력:
DEL number

기대값:
(integer) 1

----------------------------------------------------------------

[D13] 같은 키를 다시 삭제

입력:
DEL number

기대값:
(integer) 0

----------------------------------------------------------------

[D14] 명령어 대소문자 혼합

입력:
gEt greeting

기대값:
"다시 안녕"

명령어는 대소문자를 구분하지 않지만 키와 값의 대소문자는 그대로 유지된다.

----------------------------------------------------------------

[D15] EXIT으로 종료

입력:
exit

기대값:
별도 출력 없이 mini-redis 프로그램이 종료된다.

================================================================
2. 메모리 제한과 LRU 자동 제거 — 별도의 새 mini-redis 세션
================================================================

이 시나리오의 `a A`, `b B`, `c C`, `d D`는 각각 UTF-8 기준 2바이트다.
`e EEEEE`는 키 1바이트와 값 5바이트를 합쳐 6바이트다.

[M01] 최대 메모리 6바이트 설정

입력:
CONFIG SET maxmemory 6

기대값:
OK

----------------------------------------------------------------

[M02] 첫 번째 키 저장

입력:
SET a A

기대값:
OK

현재 LRU 순서(MRU → LRU): a
현재 used_memory: 2

----------------------------------------------------------------

[M03] 두 번째 키 저장

입력:
SET b B

기대값:
OK

현재 LRU 순서(MRU → LRU): b → a
현재 used_memory: 4

----------------------------------------------------------------

[M04] 세 번째 키 저장

입력:
SET c C

기대값:
OK

현재 LRU 순서(MRU → LRU): c → b → a
현재 used_memory: 6

제한과 정확히 같은 크기는 허용된다.

----------------------------------------------------------------

[M05] a를 조회해 MRU로 이동

입력:
GET a

기대값:
"A"

현재 LRU 순서(MRU → LRU): a → c → b

----------------------------------------------------------------

[M06] 새 키 저장으로 제한 초과

입력:
SET d D

기대값:
OK

d를 먼저 저장하면 used_memory가 8이 된다. tail에 있던 b를 제거한 뒤 6이 된다.
현재 LRU 순서(MRU → LRU): d → a → c

----------------------------------------------------------------

[M07] 제거된 b 조회

입력:
GET b

기대값:
(nil)

없는 키 GET은 LRU 순서를 바꾸지 않는다.

----------------------------------------------------------------

[M08] 첫 번째 자동 제거 결과

입력:
INFO memory

기대값:
used_memory:6
maxmemory:6
evicted_keys:1

----------------------------------------------------------------

[M09] 현재 키 확인

입력:
KEYS

기대 키:
"a", "c", "d"

출력 순서는 고정되지 않는다.

----------------------------------------------------------------

[M10] 제한과 정확히 같은 단일 엔트리 저장

입력:
SET e EEEEE

기대값:
OK

e 자체의 크기는 6이므로 저장 가능하다. 저장 직후 전체 사용량은 12가 되고,
기존 LRU 순서의 tail부터 c, a, d가 차례로 제거되어 e만 남는다.

----------------------------------------------------------------

[M11] 반복 제거 결과

입력:
INFO memory

기대값:
used_memory:6
maxmemory:6
evicted_keys:4

----------------------------------------------------------------

[M12] 단일 엔트리 자체가 제한보다 큰 경우

입력:
SET huge 123

기대값:
(error) OOM command not allowed when used_memory > 'maxmemory'

`huge` 4바이트와 `123` 3바이트의 합은 7바이트다. 기존 e는 보존된다.

----------------------------------------------------------------

[M13] OOM 뒤 상태 보존 확인

입력:
GET e

기대값:
"EEEEE"

----------------------------------------------------------------

[M14] OOM 뒤 메모리 정보 확인

입력:
INFO memory

기대값:
used_memory:6
maxmemory:6
evicted_keys:4

OOM으로 거부한 키는 사용량과 제거 횟수를 바꾸지 않는다.

----------------------------------------------------------------

[M15] 0으로 무제한 설정

입력:
CONFIG SET maxmemory 0

기대값:
OK

0은 0바이트 제한이 아니라 메모리 제한을 적용하지 않는다는 뜻이다.

----------------------------------------------------------------

[M16] QUIT으로 종료

입력:
quit

기대값:
별도 출력 없이 mini-redis 프로그램이 종료된다.

================================================================
3. TTL과 지연 삭제 — 별도의 새 mini-redis 세션
================================================================

[T01] 만료되지 않을 기준 키 저장

입력:
SET persistent P

기대값:
OK

이 엔트리의 크기는 `persistent` 10바이트와 `P` 1바이트를 합쳐 11바이트다.

----------------------------------------------------------------

[T02] TTL을 시험할 키 저장

입력:
SET temp old

기대값:
OK

----------------------------------------------------------------

[T03] TTL 설정

입력:
EXPIRE temp 100

기대값:
(integer) 1

StoreEntry에는 절대 만료 시각이 저장되고 최소 힙에는 `(expire_at, "temp")`가 추가된다.

----------------------------------------------------------------

[T04] 남은 TTL 확인

입력:
TTL temp

기대값:
(integer) <남은 초>

바로 실행하면 보통 99가 표시된다. 시간의 소수 부분을 버리므로 100이 아닌 값이 나올 수 있다.

----------------------------------------------------------------

[T05] 없는 키에 EXPIRE

입력:
EXPIRE missing 100

기대값:
(integer) 0

----------------------------------------------------------------

[T06] SET으로 기존 TTL 초기화

입력:
SET temp renewed

기대값:
OK

과거 힙 기록은 당장 찾아서 제거하지 않지만, StoreEntry의 현재 expire_at은 None이 된다.

----------------------------------------------------------------

[T07] TTL 초기화 확인

입력:
TTL temp

기대값:
(integer) -1

----------------------------------------------------------------

[T08] 0초로 즉시 만료

입력:
EXPIRE temp 0

기대값:
(integer) 1

----------------------------------------------------------------

[T09] 즉시 만료된 키 조회

입력:
GET temp

기대값:
(nil)

----------------------------------------------------------------

[T10] 즉시 만료된 키의 TTL

입력:
TTL temp

기대값:
(integer) -2

----------------------------------------------------------------

[T11] 실제 시간 경과로 만료할 키 저장

입력:
SET short S

기대값:
OK

----------------------------------------------------------------

[T12] 2초 TTL 설정

입력:
EXPIRE short 2

기대값:
(integer) 1

이 명령 뒤 3초 이상 기다린 다음 T13을 입력한다.

----------------------------------------------------------------

[T13] 만료 뒤 GET

입력:
GET short

기대값:
(nil)

GET은 먼저 만료 여부를 확인하고, 만료된 항목을 데이터·LRU·메모리에서 제거한다.

----------------------------------------------------------------

[T14] 만료 정리 뒤 키 개수

입력:
DBSIZE

기대값:
(integer) 1

persistent만 남는다.

----------------------------------------------------------------

[T15] TTL 만료가 eviction에 포함되지 않는지 확인

입력:
INFO memory

기대값:
used_memory:11
maxmemory:0
evicted_keys:0

일반 삭제와 TTL 만료는 evicted_keys를 증가시키지 않는다.

----------------------------------------------------------------

[T16] 종료

입력:
EXIT

기대값:
별도 출력 없이 mini-redis 프로그램이 종료된다.

================================================================
4. 오류와 OOM 경계 — 별도의 새 mini-redis 세션
================================================================

[E01] 존재하지 않는 키 조회

입력:
GET missing

기대값:
(nil)

----------------------------------------------------------------

[E02] 존재하지 않는 키 삭제

입력:
DEL missing

기대값:
(integer) 0

----------------------------------------------------------------

[E03] 존재하지 않는 키의 TTL

입력:
TTL missing

기대값:
(integer) -2

----------------------------------------------------------------

[E04] 4바이트 제한 설정

입력:
CONFIG SET maxmemory 4

기대값:
OK

----------------------------------------------------------------

[E05] 기존 상태 준비

입력:
SET a A

기대값:
OK

현재 used_memory는 2다.

----------------------------------------------------------------

[E06] 새 키의 단일 엔트리 OOM

입력:
SET long X

기대값:
(error) OOM command not allowed when used_memory > 'maxmemory'

`long` 4바이트와 `X` 1바이트의 합은 5바이트다.

----------------------------------------------------------------

[E07] OOM 뒤 기존 값 확인

입력:
GET a

기대값:
"A"

----------------------------------------------------------------

[E08] 기존 키 덮어쓰기의 단일 엔트리 OOM

입력:
SET a 1234

기대값:
(error) OOM command not allowed when used_memory > 'maxmemory'

키 1바이트와 새 값 4바이트의 합은 5바이트다. 기존 값 A는 변경되지 않는다.

----------------------------------------------------------------

[E09] 기존 값 보존 확인

입력:
GET a

기대값:
"A"

----------------------------------------------------------------

[E10] OOM 뒤 메모리 상태 보존

입력:
INFO memory

기대값:
used_memory:2
maxmemory:4
evicted_keys:0

----------------------------------------------------------------

[E11] SET 인자 부족

입력:
SET only-key

기대값:
(error) ERR wrong number of arguments for 'set' command

----------------------------------------------------------------

[E12] GET 인자 초과

입력:
GET a extra

기대값:
(error) ERR wrong number of arguments for 'get' command

----------------------------------------------------------------

[E13] 정수가 아닌 maxmemory

입력:
CONFIG SET maxmemory abc

기대값:
(error) ERR value is not an integer or out of range

----------------------------------------------------------------

[E14] 음수 maxmemory

입력:
CONFIG SET maxmemory -1

기대값:
(error) ERR value is not an integer or out of range

----------------------------------------------------------------

[E15] CONFIG 하위 명령 문법 오류

입력:
CONFIG GET maxmemory 4

기대값:
(error) ERR syntax error

----------------------------------------------------------------

[E16] INFO 하위 명령 문법 오류

입력:
INFO cpu

기대값:
(error) ERR syntax error

----------------------------------------------------------------

[E17] EXPIRE 정수 파싱 오류

입력:
EXPIRE a abc

기대값:
(error) ERR value is not an integer or out of range

----------------------------------------------------------------

[E18] 존재하지 않는 명령

입력:
HELLO

기대값:
(error) ERR unknown command 'HELLO'

----------------------------------------------------------------

[E19] 닫히지 않은 큰따옴표

입력:
GET "broken

기대값:
(error) ERR syntax error

파싱 단계에서 처리되므로 Store 명령은 호출되지 않는다.

----------------------------------------------------------------

[E20] 오류 뒤 상태 유지

입력:
DBSIZE

기대값:
(integer) 1

앞선 오류 뒤에도 a가 남아 있고 REPL은 다음 명령을 계속 받는다.

----------------------------------------------------------------

[E21] QUIT으로 종료

입력:
QUIT

기대값:
별도 출력 없이 mini-redis 프로그램이 종료된다.

================================================================
5. 입력 대기 중 종료 동작
================================================================

[X01] Ctrl+C

입력:
입력 대기 상태에서 Ctrl+C

기대값:
줄바꿈 뒤 traceback 없이 프로그램이 종료된다.

----------------------------------------------------------------

[X02] Ctrl+D

입력:
입력 대기 상태에서 Ctrl+D

기대값:
줄바꿈 뒤 traceback 없이 프로그램이 종료된다.

Ctrl+Z는 Unix 셸의 작업 중지 기능이며 이 프로그램이 별도로 처리하는 종료 명령이 아니다.
